# Context Assembler DSH — 规划摘要（2026-08-20）

> 来源：与外部专家的设计评审对话（DeepSeek 分享会话，2026-08-19/20）。
> 本文档把对话中收敛的设计意图固化为**规划基线**，作为 README「项目介绍」与后续迭代的参照。
> 配套：[docs/PROGRESS-2026-08-20.md](PROGRESS-2026-08-20.md)（进度汇编）、[docs/DESIGN.md](DESIGN.md)（设计意图与 Hermes 对照）。

## 一、一句话定位

**Context Assembler（CA）不是压缩插件，而是一台「算力置换 + 上下文编排」引擎**：
在每轮对话的间隙，用本地小模型「离散、低带宽」的空闲算力，替代云端大模型在压缩会话历史时的「瞬发、高带宽」算力需求；为保护云端 prompt 缓存命中，把这一置换**按话题块打包**，而非逐 token 动态重排。

## 二、核心洞察（外部专家对话收敛）

1. **算力置换**（对话金句）：
   > 用本地小模型离散到每个对话轮间隙的低带宽算力，应对云端大模型在压缩对话轮的瞬发大带宽算力需求。
   云端 LLM 每轮都要把整段历史重发一遍（token 计费 + 信息稀释）；会话压缩本是一次瞬发的高算力峰值。把它卸载到本地空闲期，是成本结构上的根本改善。
2. **缓存折中 → 按话题块打包**：
   理想形态是「按与当前提问的关系」自由调节每一步的压缩程度；但为不破坏云端 prompt 缓存命中，改为**按话题块整体处理**——块内前缀稳定（缓存友好），仅尾部原始数据保护区（`tailN`）可变；只有发生话题切换时，才重新评估各话题块的摘要简写并形成新的汇编前缀。
3. **动态降门槛切块（防粘连）**：
   `topicSplitStartChars` → `topicSplitPeakChars` 之间**线性降低**切块所需 Jaccard 相似度门槛；即使两轮内容完全一致，到达峰值也强制切块——避免超长对话粘连成单一巨大话题块、失去缓存优势。
4. **质量目标 = 单位 token 互信息密度**：
   花最少的 token，给云端喂「每 token 互信息密度最大」的上下文。据此建立 MI 损失/密度评估体系（指标模型 ↔ 实测报告 ↔ A/B 归因 ↔ 效能评估），见 [docs/PROGRESS-2026-08-20.md](PROGRESS-2026-08-20.md) §三。

## 三、三条工程红线（专家提醒，避免「压缩等于白做」）

1. **压缩工具必须配对**：用 LLM 做语义摘要，而非二进制/gzip 式压缩——模型无法解压二进制流，注入前必须是自然语言或结构化文本。
2. **压缩率 × 信息密度平衡**：摘要必须保留三要素——**未完成的意图**、**关键事实**（ID/日期/数据）、**当前对话状态**；丢任何一项，模型下次都不知道该回什么。
3. **时间戳与顺序必须保留**：历史被打乱会混淆因果，须显式标注时间线。

> 落地映射：CA 的摘要路径（话题块摘要 / 工具轮改写 / Fct-OODA）全部由本地 LLM 生成结构化文本（保留事实锚点），非裁剪丢弃；`tailN` 尾部保护区保住当前轮原始信息。

## 四、与 DSH 生态的定位（互补，而非替代）

| 机制 | 触发方式 | 目标 | 与 CA 的关系 |
|------|----------|------|--------------|
| DSH compaction-basic（原生） | 被动：上下文窗口压力超阈值才触发 | 防溢出（裁剪最旧历史） | **互补**——CA 主动编排、为缓存而生 |
| dsh-compaction-instant | 确定性近无损压缩（工具轮→单行、工具结果→指针，实测 91% 压缩率） | 省 token | **同源**——CA 的「工具轮压缩」思路可对标 |
| billion-context-dsh | 模型自决何时压缩、压缩什么 | 智能压缩 | **同方向**——CA 以话题块为粒度 |
| **CA-DSH（本插件）** | **主动：每轮 pre-step 介入** | **缓存命中 + 信息密度 + 成本** | — |

## 五、路线图（与 GitHub Issues R1/R2/R3 对齐）

- **R1 话题块定级升级**：实体图距离为主路径（7.1 P3），embedding 形心半径降为实体缺失时的兜底；尾部保护保持硬编码最后 2 个 user 轮。
- **R2 本地 LLM 摘要 + 热路径异步化**：7.1 P2 post-tool 4B 回填 + 7.2 K1 思考卡 L1 提炼（**已落地**）；pre-step 只做毫秒级检测/注入，摘要与投影复测移出热路径。
- **R3 reality 提问云改造**：realities 表补 `query_text`/`query_centroid_json`/`query_count`，注入预筛改用提问云形心距离（未排期，顺延 7.x）。
- **未决/待议**（外部对话遗留）：当前 DSH 版本无 eLM 层后的装配策略；单位 token 互信息密度的进一步优化（对话中已指出「每 token 互信息密度较低」方向）。
